# Receipt dispatcher regression

`receipt_test.cpp` checks 10,000 outstanding receipts in forward, reverse and
shuffled order, duplicate/unknown IDs, and a callback that clears/re-enters and
destroys its dispatcher. The parent cdcmoud build registers it as
`cdcmoud_receipt_test` in CTest.

The dispatcher uses `unordered_map` lookup and erases an entry before invoking
its callback. No iterator or callback reference survives user code. The callback
remains one-shot even when it clears or destroys the dispatcher.

Callbacks only record counters and re-entry outcomes. Assertions execute after
dispatch returns, so the production exception handler cannot swallow a failed
assertion and turn it into a passing regression test.

Receipt IDs are opaque hexadecimal strings generated by `std::to_chars`.
Previously `to_hex_print` discarded zero bytes: 1 and 256 both became `01`.
The dispatcher now emits distinct `1` and `100`, and rejects sequence exhaustion
instead of wrapping. The shared conversion utility and subscription dispatch
are unchanged. `create()` returns a view valid until that receipt is dispatched
or the handlers are cleared/destroyed; connection send code copies it into the frame.

The public `send(frame, callback)` API is unchanged. Fresh connection/parser
creation, transaction splitting and publication deadlines are implemented by
cdcmoud, not this library.

`connection::prepare(send)` reserves a real receipt ID and returns a move-only
`prepared_frame` with final wire bytes, without socket output or a pending callback.
`size()` includes the receipt header and NUL. `send(std::move(prepared), callback)`
registers the callback and consumes those exact bytes. It rejects a different
connection/session. Discarding an unsent prepared frame requires no cleanup;
its reserved sequence number is never reused. Pending receipt callbacks are still
bounded by the currently sent part, rather than by all prepared messages.
Existing `send(frame, callback)` callers keep their original path and behavior.

The parent publisher wire tests independently check F/F−1 limits, escaping,
content-length, receipt growth across hexadecimal `f`→`10`, and no BEGIN on a
preflight failure. They also exercise cancellation after preparation and callbacks
through the production parser. Assertions run after the final teardown/drain.
